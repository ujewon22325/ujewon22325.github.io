# CardWise

한국어로 결제내역을 등록하고 전월실적과 카드 혜택을 따로 살펴보는 React·TypeScript 앱입니다. 기존 운동노트와 분리된 `/cardwise/` 경로를 사용합니다. 현재 구현 범위는 **Phase 1~2**입니다. GitHub Pages 배포 경로는 `/cardwise/`입니다.

## 실행

Node.js 22 이상을 권장합니다. 개발 서버는 회원가입·서버·유료 API·비밀키 없이 동작합니다.

```sh
cd /workspace/ujewon22325.github.io/cardwise
npm ci
npm run dev
```

다른 컴퓨터에서는 저장소의 `cardwise` 디렉터리로 이동하세요. Vite가 출력하는 `/cardwise/` 경로에서 실행합니다. 개발 환경은 기존 체크아웃을 사용하며 Git worktree를 추가로 만들 필요가 없습니다.

```sh
npm test               # 순수 계산 / 가져오기 / 데이터 검증
npm run test:e2e       # Playwright: 데스크톱 + Pixel 7 크기
npm run typecheck
npm run build          # 타입 검사 후 dist/ 생성
npm run preview        # 프로덕션 결과 로컬 확인
```

이 클라우드 환경에서는 `/usr/bin/chromium`을 사용합니다. 해당 실행 파일이 없는 기기에서는 `npx playwright install chromium`으로 Playwright 브라우저를 설치하세요. 테스트에는 실제 개인 거래를 사용하지 않습니다.

## 처음 사용하기

1. **6개월 샘플 둘러보기**로 화면을 살펴보거나, 카드 관리에서 본인의 카드를 직접 등록합니다.
2. **규칙 편집**에서 약관의 실적·혜택·한도를 입력하고 검증 상태를 선택합니다. 사용자가 등록한 근거는 자동으로 공식 인증되지 않습니다.
3. **내역 가져오기**에서 CSV/XLSX를 선택하고 승인일·가맹점·금액 등 열을 연결합니다. 매핑에 이름을 붙여 저장할 수 있습니다. XLSX는 첫 시트를 읽습니다.
4. **설정**에서 이전 달을 선택하고, 모든 카드 이용내역을 등록한 경우에만 월 자료 확인을 표시합니다. 가져오기나 수동 수정은 해당 월 확인을 해제합니다.
5. 이번 달을 선택해 대시보드와 결제내역의 예상 혜택을 확인합니다. 혜택 금액을 누르면 계산 근거를 볼 수 있습니다. 내역의 **편집**에서 업종·결제수단·원거래 연결을 수정할 수 있습니다.
6. 명세서의 실제 혜택을 확인한 경우 **실제 확정 혜택**을 직접 입력합니다. 예상값과 별도로 집계됩니다.

실제 카드 7종(Youth Club A/B팩은 별도 항목)의 이름만 기본 제공하며, 조건은 모두 **검증 필요**입니다. 확인되지 않은 할인율·한도·연회비를 실제 값처럼 제공하지 않습니다. 기본 0원 연회비도 미확인이라고 표시합니다. 계산에서 제외되는 미검증 항목은 **미확정**으로 남습니다.

가상 생활 2%와 쇼핑 5% 카드는 실제 금융 상품이 아닙니다. 샘플 모드에는 개인정보 없는 2026년 5~10월 54건만 표시됩니다. 내 데이터와 샘플은 화면·계산에서 분리하며 전체 백업에는 두 종류가 모두 들어갑니다. 샘플 첫 달은 직전 월 자료가 없어 혜택을 판정하지 않습니다.

## 구현한 기능

- 대시보드, 6개월 소비/예상 혜택 그래프, 카드별 실적 상태, 최근 거래
- CSV(UTF-8/EUC-KR)·XLSX 업로드, 열 매핑 저장/재사용, 미리보기, 전체 행 유효성 검사
- 거래 고유 ID / 파일 SHA-256 + 행 위치 기반 중복 탐지. 동일 가맹점·금액의 별도 거래는 보존
- 분류 사전의 키워드·업종 편집, 수동 거래 편집, 명시적 재분류
- 카드 생성·수정·복제·삭제, 규칙 버전·근거 URL·확인일·적용 기간 관리
- 별도 TypeScript 계산 엔진: 전월실적, 제외 조건, 청구/현장 할인·캐시백·포인트 구분, 사용자 포인트 가치, 실질 부담, 거래별 설명
- 통합·혜택별·업종별·가맹점별 월 한도, 건별/일별 한도, 최소금액, 결제수단, 자동납부, 국내/해외, 온라인/오프라인 조건
- 날짜순 한도 적용, 절사/반올림/올림, 실적 구간별 통합 한도, 신규 발급 유예 조건
- 한 장의 카드로 결제하는 비교, 실제 이전 배분 유지/이전 배분도 변경하는 가정, 50만/100만원 실적 가정
- Dexie/IndexedDB 저장, 다크모드, 반응형 화면, 검증된 JSON 백업·교체 복원, 결과 CSV 내보내기, 전체 삭제

## 계산 계약과 제약

- **확정 혜택이 아닙니다.** 모든 계산값은 입력한 규칙 기준 예상값입니다. 검증 필요 규칙, 누락된 매입일·원화 청구금액, 미확인 환불 등은 보류하며 부분 합계를 표시합니다.
- 혜택 판정과 실적 판정은 별도 상태입니다. 전월 혜택을 몰라도 할인 여부와 무관한 전월 인정액은 계산할 수 있습니다. 할인 받은 거래를 실적에서 제외하는 카드라면 혜택 판정 부재도 실적을 미확정으로 만듭니다.
- `knownMonths`는 **모든 카드 자료가 완전하다는 사용자 선언**입니다. 누락 카드도 0원으로 해석되므로 일부 카드만 가져온 달에는 체크하지 마세요. 매입일 기준 및 1일이 아닌 시작일을 쓰는 경우 해당 산정기간 자료 전체를 확인해야 합니다.
- 금액은 원화 정수로 검증합니다. 외화 거래는 원화 청구금액이 없으면 환율을 추정하지 않습니다. 화면의 승인금액은 원래 거래금액을 보존합니다. 외화 원화 청구금액 미확인 거래는 대시보드 원화 합계에서 제외합니다.
- 각 버전의 적용 기간은 **승인일** 기준입니다. 혜택·실적 산정 날짜와 순서는 버전에 등록한 승인일/매입일 기준을 따릅니다. 현재는 혜택 기간과 실적 기간에 동일 시작일을 적용합니다. 서로 다른 산정기간이나 예외적인 약관은 지원하지 않습니다.
- 취소는 **같은 카드의 원거래 ID**를 명시적으로 연결해야 합니다. 취소월 반영은 원래 혜택·실적의 비례 금액을 누적 절사 규칙으로 역산합니다. 원거래월 반영은 그 원거래의 혜택·실적을 줄여 재계산합니다. 초과 취소와 미확인 원거래는 보류합니다. 취소는 새로운 소비로 가산하지 않습니다.
- 원거래월 취소가 뒤늦게 등록되면 과거 예상 결과도 바뀝니다. 취소월 방식으로는 원래 혜택이 미확정이면 취소 혜택도 미확정입니다. 카드사의 특별한 취소·재정산 규칙은 별도 확장이 필요합니다.
- 취소 시 **통합한도** 복원만 지원합니다. 업종·혜택·가맹점·일별 한도는 복원하지 않습니다. 그러한 약관의 카드는 해당 규칙을 정확히 모델링하기 전까지 검증 필요로 유지하세요.
- 포인트 한도는 사용자 환산 가치의 원화 금액으로 설정합니다. 소수 포인트는 적립하지 않으며 원화 가치는 절사합니다. 포인트 자체 단위 한도, 선불 차감·리볼빙·복잡한 할부 취소 등은 지원하지 않습니다.
- 혜택은 우선순위 내림차순, 같은 순위에서는 ID순으로 적용합니다. 앞선 혜택이 적용된 뒤 중복 허용이 켜진 후속 혜택만 추가됩니다. 혜택 합계는 거래 원금을 넘지 않습니다.
- 단독 비교에서 선택 월 거래는 전액 같은 카드에 이동합니다. 이전 달의 실제 배분 유지와 이전 거래까지 모두 이동하는 가정은 별도입니다. 이용 가능 카드 조건이나 과거 환불 연결이 해결되지 않으면 시나리오를 확정하지 않습니다.
- 연회비·발급비용은 저장하지만 월별 혜택에서 차감하지 않습니다. 연간 순혜택 분석은 미구현입니다.
- 큰 파일은 최대 20MB/5만 행까지 허용하지만, 5만 건 전체의 계산·렌더링 성능은 아직 검증하지 않았습니다. 결제 표는 검색 결과의 첫 500행을 표시하고 계산에는 전체 내역을 사용합니다.
- 동일 거래 ID가 없는 **서로 다른 파일**의 중복 거래는 자동으로 삭제하지 않습니다. 정상적인 반복 거래를 잘못 삭제하는 대신 사용자가 확인해야 합니다.

## 저장과 개인정보

결제내역과 카드 규칙은 `cardwise-v1` IndexedDB에 저장합니다. 업로드 파일을 서버로 보내거나 분석 API를 호출하지 않습니다. 외부 폰트·추적 스크립트도 사용하지 않습니다. 백업은 스키마 버전 1, 거래/카드/규칙/분류/매핑/설정을 검증한 뒤 단일 IndexedDB 트랜잭션으로 교체합니다. 실패하면 기존 데이터를 유지합니다.

브라우저 데이터를 지우면 기록이 사라질 수 있으니 주기적으로 백업하세요. 공유 기기에서는 다른 사용자가 금융 기록을 볼 수 있습니다. 실제 거래·백업 파일을 저장소에 추가하거나 공유하지 마세요. CSV 내보내기는 수식으로 해석될 수 있는 셀을 이스케이프합니다.

```text
src/domain/import.ts      파일 파싱·매핑·분류·중복 탐지
src/domain/sample.ts      미검증 실카드 이름과 가상 샘플
src/data/db.ts            IndexedDB 초기화·백업·복원
src/components/          shadcn/ui 패턴의 Radix/CVA 기본 UI와 편집 화면
src/App.tsx              한국어 반응형 화면

```

**Phase 3 준비:** 거래·규칙·결과가 UI에서 분리되어 있습니다. 엔진을 조합 시나리오 평가기로 재사용할 수 있습니다. 2~3장 조합, 카드별 실적 고정, 추가 온라인 소비, SKT 선택형 예제 UI, 기회비용 및 추천 배분, 다개월 누적·연간 순혜택은 아직 구현하지 않았습니다. `withSktExample`은 중복 방지 검증용 유틸리티만 있고 화면에는 노출하지 않습니다. 다음 단계에서는 이전 달 조건이 확정된 단일 월, 분할 결제 없는 거래 단위 배분을 대상으로 시작하고 전역 최적해를 검증하지 못하면 ‘추천 배분안’으로 표시해야 합니다.

**Phase 4 준비:** 백업/복원·모바일 UI·정적 프로덕션 빌드는 구현했습니다. PWA manifest/service worker·설치·오프라인 지원은 아직 구현하지 않았습니다. 별도 `/cardwise/` ID와 scope, 고유 `cardwise-` 캐시만 사용해야 합니다. 다른 앱의 캐시는 삭제하지 않아야 합니다. 현재 앱의 ‘기기 내 저장’은 새로고침 후 데이터 유지이며 오프라인 실행을 뜻하지 않습니다.

## 정적 배포

`base`는 `/cardwise/`입니다. **개발 소스는 `src/`에 있고, 루트의 `index.html`과 `assets/`는 정적 배포용 빌드 파일입니다.** `npm run build` 결과인 `dist/` 내용을 사이트의 `/cardwise/` 디렉터리에 배포하세요. 기존 `.github/workflows/deploy-pages.yml`은 main 배포 시 CardWise 설치·계산 테스트·타입 검사·빌드를 실행하고, 기존 정적 앱과 빌드 결과만 Pages artifact로 만듭니다. `node_modules`, 사용자 파일, 테스트 결과, TypeScript 소스는 artifact에 포함하지 않습니다.

```sh
cd /workspace/ujewon22325.github.io/cardwise
npm ci
npm run build
cd ..
python3 cardwise/scripts/prepare-pages.py /tmp/cardwise-pages-output
```

기존 Pages 설정이 main 브랜치를 직접 게시하는 방식이어도 실행되도록 빌드된 `index.html`과 `assets/`를 함께 관리합니다. 앱 소스를 변경한 뒤에는 `npm run stage:static`으로 이 정적 파일을 갱신하고 같이 커밋하세요. 개발 서버는 `src/index.html`을 사용하므로 정적 파일과 분리됩니다.

빈 출력 디렉터리를 사용하세요. 이 명령은 **배포하지 않고** artifact만 만듭니다. 검증 후 코드를 main에 반영하고 GitHub Pages 배포가 성공해야 공개 주소가 생깁니다. 환경 스냅샷 게시와 GitHub Pages 앱 배포는 별개입니다. main에 코드가 반영되면 GitHub Actions가 테스트와 빌드를 통과한 결과를 GitHub Pages에 자동 배포합니다.
